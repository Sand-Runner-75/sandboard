# Workspace

The first usable workspace, built on the read-only data layer in [DATA-LAYER.md](DATA-LAYER.md). Everything shown comes from what the data layer read at one pinned commit per repository; the page computes no progress figure of its own and has no control that writes anything.

## Places

- **Tree** (left, a menu button on narrow screens): projects, each with Overview, Tasks, its stages with their phases (or, when the progress output supplies no stages, its phases) and its repositories; then **Account**, with All repositories and Activity and languages. The arrow beside an item opens or closes it; the name goes to the place. **Expand all** and **Collapse all** sit above the tree, and a refresh keeps what was opened or closed. Arrow keys move, open and close groups, as in the WAI-ARIA tree pattern.
- **Overview**: the supplied figures for the whole plan and each scope (Pilot, MVP, Post-MVP) with what they are based on, then stage chips, a phase strip, the tasks waiting on someone, the repositories, and two columns side by side: **All tasks** (every task in table order with its status, each opening in Tasks; with a stage or phase picked, from the tree, the stage chips or a phase card, that stage's or phase's tasks, and **Open in Tasks** to filter them there) and **Recent activity**. A denied plan shows only its notice and the repositories that could be read.
- **Recent activity**: the project's commits, pull requests opened, merged or closed, and handoff comments, newest first, across its plan and code repositories, each with its repository, time and a link to where it happened. From each repository it reads the latest 30 commits at the pinned commit, the latest 100 pull requests and the latest 50 comments, live, and says what it could not read or cut off. It is evidence of activity: no event changes a figure, and nothing is subscribed to or remembered between visits.
- **Tasks**: the same whole-plan figures, the phase strip, filters (search, stage when the progress output supplies stages, phase, status, doer), the task list and the task details. Filters, stages and phases choose which rows and cards are shown; they never change a figure. A stage narrows the phase menu to its own phases. The list takes the whole width; with a task open, the details take a wide share beside it (stacked on narrow screens).
- **Task details**: a summary. Approved result files come first when there are any; then the row's main properties; evidence, shown separately from status ("Done" in the table is not owner approval); what it needs and which tasks wait on it, each with its status and opening that task as a tab (any not in the table is marked); the original plan notes (folded); a link to its cross-reference file when the workspace names where they are; its brief and handover (folded for a Done task); **Open as tab**, and **Review cycle**, which opens the tab at that section.
- **Tabs**: a task tab holds everything about the task in sections: Details (every column of its row, in the table's order, and the evidence), Brief, Handover, Results, Review cycle, Cross-references (link and text) and Related (needs, needed by, steps). The review cycle shows, each apart: whether the brief exists at the tab's commit; each pull request that names the task (and the code pull requests it links) with its state, merge, head and check runs at the head; the handoff comments on it in order, each labelled for the head, for an older commit or superseded; and the owner's decision, only from the recorded approval. It shows at most 10 pull requests and says how many more name the task or are linked but were not read. It is read live from GitHub when the section opens, says when, and **Read again** or a refresh reads it again. It has no button that sends, approves or merges. It keeps the project, repository, file templates and commit it was read from, and says so ("Read from … @ commit"); its documents stay those of that commit after the branch moves on. Tabs of another project are not in the page. On refresh, a tab closes when its repository is no longer mapped to its project or can no longer be read, and its documents go with it. The tab bar scrolls sideways when many tabs are open, never up and down.
- **Repository**: role, when it was read, visibility and check runs. A run counts as passing only on an explicit success; a finished run with no conclusion, or one not known here, is shown as such, never as passing. Then what GitHub says about it (description, original or fork, archived, default branch, licence, created, last push, stars, forks, open issues, size, topics, homepage as text with a link only when it is a plain `https` address), its clone address to copy (nothing is cloned or run), its languages by code bytes and its recent activity. A field GitHub does not give says "Not given by GitHub", never zero, and is kept apart from GitHub's own "none" (no licence, no main language); visibility is never assumed Public. A repository with no plan says **Plan progress: not available**, which is not 0%.
- **Repository history** (the History tab beside Overview; Left and Right move between them): the commits behind the commit the project reads, newest first, one row each with its short ID (a link to it on GitHub), title, date, the branches and tags that point at it and "read here" on the read commit. A graph beside the rows puts each commit in a lane and joins it to its parents; merges show as hollow nodes and a line that goes on into commits not read is dashed. Zoom in, Zoom out and Fit change its scale; the box scrolls to pan. The first 100 commits are read, and 100 more each time the list is scrolled to its end (or **Load older commits** at the end of the list is pressed), with no limit; the view says when it reached the start of the history or when a page could not be read, and the list keeps its place while more is read. Branches are compared with the read commit (ahead, behind and state, as GitHub counts them, with each head and whether it is protected): the first 10 GitHub lists, and Compare reads another. A compared branch's own commits get a lane of their own, read 100 at a time from its head until they reach the history read or the merge base, and the view says how many more it has that were not read; a branch ahead whose commits could not be read, or had none of its own among them, says so and keeps GitHub's counts in the table. Tags say whether their commit is in the history shown. Commits per week (the latest 12 weeks read), commits by day (the latest 26 weeks read, also as a table) and contributors (by GitHub login only, with commits not linked to an account counted and not named) cover only the commits read and say so. None of it is progress, and nothing here checks out, creates, resets or merges anything.
- **Work evidence** (the Pull requests, Issues, Actions and Releases tabs after History): each read live from GitHub as it lists them now, not at the pinned commit, 100 a page; **Load older** reads another page each time, up to 900, and the view says whether it reached the end of GitHub's list, stopped, or could not read a page (what was read stays shown). Pages that held nothing to show (an issue page of pull requests only, or runs GitHub counts but did not list) say that this is not the whole list, never that there are none, and keep the coverage line and Load older. Actions counts against GitHub's total: a page short of it says the list is not complete. Pull requests and issues have Open, Closed and All. A pull request shows its state (draft, open, merged with its time, or closed without merging), author login, branch into base, head and last update, and the task ID its title names, if any; **Show** opens its reviews, each at the commit it was given at and labelled the current head or an older commit (only reviews at the head count for it), and the check runs at its head. Commit statuses from the older status API are not read, and the view says so. Issues leave the pull requests in GitHub's issue list to their own tab and say how many; each shows its labels, assignees, comments, opened time and, once closed, the reason (completed, not planned, duplicate) and time. A run shows its workflow, title, event, branch and head, result and duration; a run not finished says **Not finished: no result yet** with its status, never a success, and a conclusion not known here is shown as GitHub gives it. Releases show tag (linked unless a draft), name, draft, pre-release or release, published time, author, and asset names, sizes and download counts; an asset name links only to GitHub's own download address for that repository's releases (any other address stays text), and no asset is fetched or opened here. A token without Pull requests, Issues or Actions access says which permission is missing. Nothing here creates, comments, reviews, merges, reruns, cancels or publishes anything, and none of it is progress or the owner's approval.
- **Files** (the last repository tab): everything at the commit the project reads, named by its full ID, and said so ("Files read at main → abc1234"). **Files** shows the whole tree GitHub lists at that commit, folders first, opened and closed one at a time, with **Find a file by path** (every word typed, files only, the first 200 matches), and says how many files and folders it holds or that GitHub cut its list (nothing is guessed for what it left out). Picking a file shows its text at that commit, line by line with line numbers, after its bytes are matched to GitHub's blob ID; a path not in this commit's tree says so and nothing is shown from another commit. Text is plain: HTML, Markdown, SVG and images are not rendered, nothing runs, and no address in it is a link. Characters that print nothing or turn the text's direction (such as U+202E, or a leading byte order mark) are shown boxed by their code, with a count. A symbolic link is not followed, another repository (submodule) is not opened, a file over 1 MB is not read, a path with characters other than letters, digits, dots, dashes, underscores and slashes is not read, and bytes that are not UTF-8 text are not shown (only their size and blob ID); each says why. At most 10,000 lines are shown, and the view says when it cut the rest. **Changes** lists the files the read commit changed against its first parent (a merge commit says so; the first commit says every file is new), with each one's change and lines added and removed; picking one shows its diff with old and new line numbers, hidden characters shown the same way, at most 5,000 lines. **Compare with a branch, tag or commit** asks GitHub for that name now and shows the changes from it to the read commit since their common ancestor, with GitHub's ahead and behind counts and both commit IDs; a name GitHub does not find says so and nothing else is compared in its place, and a name not of the plain form is not sent. A file with no text diff from GitHub (binary, or too large) says so. GitHub lists at most 300 changed files in one reply, and the view says when a change has more or GitHub says a commit's list goes on; a reply without its list of files says it could not be read, never "No file changed". Each view links to the file, commit or comparison on GitHub at the repository's web address. Nothing is edited, committed, checked out, downloaded or replayed from here.
- **Inbox** (under Account): who the token reads as, then its open pull requests, open pull requests that ask it for a review by name, and open issues assigned to it, from the first 100 open pull requests and issues of each mapped repository only. It counts every mapped repository, names each one that is still being read or could not be read (none of its lists is read), says which lists could not be read or were not read to the end, and how many open pull requests ask a team (team membership is not read). GitHub notifications, account-wide searches and repositories outside the projects are never read, and nothing is marked as read.
- **All repositories**: every repository the workspace list names or the token can read, once, with each project and role it has: visibility, original or fork (and archived), main language, topics, stars, forks, open issues, size and last push. A repository that could not be read is listed with its state and nothing else. Search (name, description, topics), visibility, language and type filters, sorting (unknown values last) and **Group by project** choose and order rows; they change no value. Nothing else in the account is listed.
- **Open a repository by name** (on All repositories): `owner/name` or `owner/name@branch` opens that repository for this visit as a code-only project marked "opened by name", with no plan and no progress. A refresh keeps it; Forget access, leaving the demo or leaving the page drops it. A repository the list already maps is shown where it is mapped. At most ten per visit.
- **Found repositories**: every repository the token can read that the workspace list does not name is shown after the listed projects, marked "found" and named without its owner (unless two share a name): as a project when it has a task table where the list's found plan files say, else as code only. All repositories says whether the token's list could be read.
- **Activity and languages**: who the token reads as (login and type only), then GitHub's counts over the mapped repositories, each saying over how many it is: repositories read, visibility, originals and forks, stars, forks and open issues; languages by number of repositories and by code bytes (with the ones that could not be read); repositories by year created (originals solid, forks hatched); lifespans from creation to last push; stars against last push, also as a table; and kind, licence and default branch counts. A notice says these are GitHub activity, not progress. No account-wide feed or contribution count is read.
- **Go to** (Ctrl K or ⌘K): places only (the account views and the inbox, projects, views, each repository's history, pull requests, issues, Actions, releases and files, the current project's tasks, themes). It does not search inside files.

## Explanations

Words and symbols that are not self-explanatory (statuses, figure labels, stages, phases, dots, evidence, repository roles, the commit line, tab sources) show a short explanation in a bubble when the pointer rests on them for a little over a second, or at once when the keyboard moves to them. The bubble can be hovered, goes when the pointer or focus leaves, and Esc hides it. The help dialog lists every explanation under "Words used here".

## States

Every surface shows one of the data layer's states with a glyph, a title and a sentence, never a blank or a zero standing in for "unknown": loading, empty, no match, missing, denied, rate limited, invalid, stale, unavailable, partial, failed and none. A phase with no rows says "No active work", never 0% or 100%. Phase dots show one dot per row up to 40 rows, then one dot per status with its exact count. Stale progress is never shown as figures. Invalid table rows are listed with their line and raw text.

## Result files

A result-file link appears only for a task whose owner approval the progress output records (`approved_results`, see DATA-LAYER.md), at the pinned commit, in a new tab. Paths the producer rejected show as "Invalid link". Without a web address from GitHub, no link is made.

## Access lifecycle

Forget, leaving the demo, a revoked or expired token, leaving the page and coming back from the browser's page cache all end the session the same way: the token field is cleared, every tree item, view, tab, dialog, Go to entry and live message is removed, and the page returns to "Nothing loaded". A refresh that loses access to a plan removes its tasks and tabs.

## Text size

Text follows the browser's own size and zoom, and grows a little with the screen: the browser's size on phones, up to an eighth more on wide screens (about 14 px body text at 390 px, about 15.75 px from 1440 px, with the usual 16 px browser setting).

## Keyboard

The help dialog (**?**) lists the keys: Ctrl K or ⌘K for Go to, **/** for search, arrows, Home and End in the tree and the task list, Enter to open, **T** to open a task as a tab, arrows and Delete on tabs, and Esc to close. The first Tab stop is a skip link to the main area. Focus stays where it was when the page redraws, and the focus ring is 3 px.

## Theme

Device, Light or Dark, for this visit only. The choice is not remembered, because the page stores nothing in the browser.

## Synthetic demo

**Show the synthetic demo** runs the same code against made-up repositories in `fixtures/demo/`, built into `demo-data.js`, with no network. It covers a current plan with stages, approved result files and a cross-reference file, a stale plan, a plan without progress, a kit with broken rows, a denied plan and a code-only project. Brief and handover text includes hostile HTML that must show as text. Its repositories have metadata (one a fork, one archived, one with fields missing), languages (one refused), commit history and pull request times for the activity feed, a description with hostile HTML and a `javascript:` homepage, pull requests with reviews at older commits and at the head, issues, workflow runs (two not finished) and releases with assets for the work evidence tabs and the inbox, an Actions list refused for the plan, and one repository no workspace names, which may only appear when opened by name.
